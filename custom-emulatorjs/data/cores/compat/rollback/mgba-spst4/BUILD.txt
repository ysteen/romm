# mGBA Splitscreen compatibility core

The included `mgba_splitscreen_libretro.so` is a qualified Linux x86_64 RetroArch core. The RetroArch application is unchanged. Install the core for your platform with **Load Core → Install or Restore a Core**.

Also download `mgba_splitscreen_libretro.info` from the room and copy it, without renaming, into the folder shown under **Settings → Directory → Core Info**. This file registers `.gba` content and the GBA Link subsystems. Close RetroArch, remove `core_info.cache` from that folder if present, then reopen it. Select **Load Core → mGBA Splitscreen**, then **Load Content** to browse for the game. The core installation browser selects DLL/SO files, not games.

If GBA files remain hidden, turn off **Settings → File Browser → Filter Unknown Extensions** temporarily. Under **Information → Core Information**, the core should show GBA as a supported extension. The info file belongs in the configured Core Info directory; the DLL belongs in the Cores directory. Windows must not append `.txt` to the info filename.

The native core accepts one `.gba` through **Load Content** and boots the **Players per ROM** setting directly (default: 2). For three or four players, change that option under **Quick Menu → Core Options**, then reload the game before joining. It does not open the in-core player-count menu, so a Netplay-triggered reload can initialize without menu input. The **GBA Link 2/3/4 Player** subsystems remain available; use the same cartridge in every slot. RetroArch handles supported ZIP archives before passing the ROM to the core; extract the `.gba` first when troubleshooting archive browsing.

Native startup patch: mgba-native-startup.patch. Manifests identify this build as `nativeStartup: configured-players-v1` and include `startupPatchSha256`. The patch changes startup only; the SPST4 state format and library compatibility version remain unchanged. Replacement binaries passed ABI/export/checksum inspection; interactive RetroArch validation is pending user testing.

State patch: mgba-rollback-state.patch

The local `retroarch-netplay-bridge` project provides `scripts/build-retroarch-rollback-mgba.sh`. Run it in a fresh `COMPAT_WORK` directory with the prepared Emscripten and RetroArch frontend dependencies; use `COMPAT_BUILD_WEB=1` for the matching web package. `manifest.json` records the tested artifact hashes.

The exact library version is `0.1.0-f1d5975-rollback1`. Both participants need matching core options and cartridges. Windows x64, x86 and ARM64 DLLs and Android arm64-v8a, armeabi-v7a, x86_64 and x86 shared libraries are in native/. Android builds require API 24 or later and use 16 KiB ELF alignment. Select the architecture of the installed RetroArch app; browser detection is only a suggestion. Each target has its own manifest.json. Windows x64/x86 library loading is checked; Android and Windows ARM64 device gameplay is not qualified.
